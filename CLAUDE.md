# CLAUDE.md — Aturan Proyek (BACA DULU, SEBELUM MENYENTUH APA PUN)) 

File ini aturan tunggal proyek. Setiap kali zip proyek di-upload dan diminta menambah fitur, ubah, atau perbaiki sesuatu, AI wajib membuka file ini lebih dulu, bahkan kalau user tidak menyebut file apa pun. Kalau permintaan user bertabrakan dengan aturan di sini, permintaan user yang menang, lalu catat perubahannya di bagian Catatan Arsitektur.

## 1. Aturan kode (mutlak)

- Tidak ada komentar di kode hasil akhir (Kotlin, C++, XML, Gradle, CMake) kecuali user memintanya.
- Nama class generik dilarang total: Manager, Helper, Util, Utils, Handler, Data, Info, Item, Base, Common, Service (kecuali Android Service sungguhan). Pakai nama yang menyebut tugas persisnya (contoh: TreeScan, TaskBoard, VtScreen).
- Nesting berlebihan dilarang total. Di Compose: jangan bungkus Box/Column/Row yang tidak punya fungsi. Satu wadah per tujuan.
- Hasil tidak boleh terasa generik atau buatan template. Ikuti bahasa visual yang sudah ada di Theme.kt (Nx* tokens, NxButton, NxField, NxDialog) dan jangan menambah gaya baru tanpa alasan.
- Aturan ini dijalankan sendiri, tanpa menunggu diingatkan.

## 2. Konsep: fitur berat = Task + C++

Ada dua kewajiban terpisah. Satu fitur bisa kena keduanya.

**Task (wajib untuk pekerjaan yang lama):** semua pekerjaan yang bisa lebih dari ~1 detik atau menyentuh banyak file/jaringan harus jalan lewat `TaskBoard.start(kind, title, stoppable) { run -> ... }`. Tidak boleh dijalankan langsung di coroutine layar atau memblok UI.
- Isi progres: `run.total`, `run.done`, `run.totalBytes`, `run.bytes`, `run.detail`, `run.skipped`.
- Cek `run.stop` di setiap iterasi/chunk dan lempar `TaskStopped`. Kalau pekerjaan tidak bisa dihentikan, set `stoppable = false`.
- Panggil `TaskBoard.publish()` setelah memajukan progres (sudah di-throttle).
- Tambah `TaskKind` baru bila jenisnya belum ada.
- Tampilan sudah otomatis: `TaskStrip` (di atas daftar file), layar Tasks, notifikasi progres, wakelock. Pasang `TaskStrip()` di layar baru yang menampilkan daftar file.
- Task harus selamat saat app ditinggal atau dihapus dari recents (ditopang KeepAliveService). Jangan menyimpan Context Activity di dalam task; pakai `applicationContext`.
- Layar yang menampilkan hasil harus refresh sendiri saat `TaskBoard.finished` berubah.

**C++ (wajib untuk logika berat):** logika yang CPU-bound atau memproses data besar ditaruh di `app/src/main/cpp`, UI tetap Kotlin.
- Masuk C++: pemindaian/penghitungan pohon folder, parsing dan render grid terminal, pencarian/diff teks besar, hashing, kompresi, filter/sort jutaan entri, dekode data biner.
- Tetap Kotlin: UI Compose, navigasi, SFTP/JSch dan socket (I/O jaringan), penyimpanan preferensi, glue Android.
- Semua file C++ masuk target `nxcore` di `CMakeLists.txt`. Satu library, satu `System.loadLibrary("nxcore")`.
- Pola: inti C++ murni di `*.h/*.cpp` tanpa JNI, lalu `*_jni.cpp` tipis yang hanya menerjemahkan JNI. Sisi Kotlin berupa `object` berisi `external fun` (contoh: `TermCore`, `TreeScan`) dan pembungkus kecil yang menjaga API lama.
- Thread: kunci di sisi Kotlin (`synchronized`), C++ tidak menyimpan state global.
- Wajib diuji di host dengan harness kecil dan `-fsanitize=address,undefined` sebelum diserahkan. JNI diuji dengan stub `jni.h`.
- ABI yang dibuild: arm64-v8a, armeabi-v7a, x86_64. Jangan menghapus.
- Bila fungsi JNI di Kotlin punya cadangan Kotlin (seperti `TreeScan.scanSlow`), jaga keduanya tetap setara.

**Cara memutuskan:** tanya dua hal. (1) Bisa lama atau banyak? Jadikan Task. (2) CPU-bound atau data besar? Jadikan C++. Kalau keduanya ya, Task yang memanggil fungsi C++.

## 2a. Struktur folder dan navigasi (mutlak)

- Drawer (hamburger): bagian NAVIGATION berisi Home, Tasks, Task Error, Settings. Bagian TOOLS berisi Terminal, Internal, Root, Browser, Cashflow, AI Agent; tiap entri punya ikon, judul, dan subjudul, dan daftar bisa di-scroll. Home tidak memuat tombol pintasan tool. Layar baru lewat `Route` di `Shell.kt`, ikut di `titleOf`, dan ditambah sebagai `DrawerItem`.
- Tombol Back (mutlak): setiap layar fitur wajib punya `NxIconButton(NxIcon.Back, tr("Back"))` di `nav` milik `NxBar`. Di `AppShell`, Home memakai Menu di `nav`; semua rute lain memakai Back (ke Home) di `nav` dan Menu di `actions`. Layar penuh di luar shell (`VpsScreen`, `ViewerScreen` dan viewer-nya) memasang Back sendiri. Layar baru tidak boleh lolos tanpa Back.

## 2a2. Animasi (mutlak)

- Semua animasi harus ringan: ubah nilai lewat `graphicsLayer { }` (fase layer, tanpa recomposition per frame), `Animatable`, `animateFloatAsState`, atau `rememberInfiniteTransition`. Jangan membaca state animasi di komposisi untuk `Modifier.padding/size/offset` yang memicu relayout tiap frame.
- Pakai yang sudah ada: `Modifier.nxEnter(index)` (muncul bertahap), `Modifier.nxPulse()` (berdenyut), `nxTap` (skala saat ditekan), `NxButton`, `NxDialog` (muncul dengan skala), transisi rute di `AppShell`, `animateItemPlacement` di daftar Lazy.
- Durasi 90 sampai 450 ms. Animasi tak berujung hanya untuk indikator aktif (pekerjaan berjalan, mengetik) dan harus berhenti saat tidak terlihat.
- Daftar Lazy: jangan memutar ulang animasi masuk setiap item kembali ke layar; tandai item yang sudah tampil (lihat `AiTurn.settled`).

## 2b. Aturan buka file dan penyimpanan (mutlak)

- Tap file tidak pernah langsung ke editor. Semua jalur buka file lewat `FileOpen.start(...)`: ekstensi media dicek dulu, selain itu 8 KB awal file disniff oleh C++ (`FileSniff`, `filesniff.cpp`). Hasilnya `OpenKind` (Text, Image, Audio, Video, Binary) dan `ViewerScreen` memilih layar.
- Teks hanya bisa diedit sampai 256 KB. Di atasnya wajib `TextPager`: read-only, indeks baris dibangun C++ lewat Task, isi dibaca per baris dengan `RandomAccessFile`, baris panjang dibelah 4096 byte. Biner tidak pernah didekode jadi String kecuali lewat "Read as text" yang selalu read-only.
- Dilarang `readBytes()`/`readText()`/`readAllBytes()` pada file tanpa batas ukuran. Pembacaan harus punya batas (lihat `readCapped`).
- Media tidak pernah dimuat ke heap: audio dan video lewat ExoPlayer dari `File`, gambar lewat `inSampleSize` (sisi terpanjang maksimal 2560 px).
- File dari Root atau VPS dipindah ke cache dulu lewat Task (`StagedGate`, `MediaStage`) sebelum dibuka. Cache dibersihkan saat app mulai.
- Audio lewat `Playback` (satu ExoPlayer bersama) dan `PlaybackService` (MediaSession, notifikasi, kontrol kunci layar). UI tidak membuat player audio sendiri. Video memakai player sendiri dan menjeda audio.
- Semua data fitur disimpan di `/storage/emulated/0/Uplink/{fitur}` lewat `AppFolder.dir("fitur")`, tulis dengan `AppFolder.writeAtomic`. Fitur yang ada: `flow` (cashflow), `browser` (riwayat, mesin DevTools), `vps` (hasil Save to phone, per nama server), `errors` (log Task Error), `crash` (last.txt). Bila akses semua file belum diberikan, `AppFolder` jatuh ke folder app.

## 2c. Bahasa (mutlak)

- Semua teks yang dilihat user (label, judul, toast, pesan error, judul Task, notifikasi, deskripsi ikon) wajib lewat `tr("English text")`. Kunci adalah teks Inggris itu sendiri. Dilarang menulis literal UI mentah.
- Teks bersisipan pakai placeholder `{0}`, `{1}`: `tr("Delete {0}?", name)`. Jangan merakit kalimat dengan `+` atau template `$`, dan jangan membuat bentuk jamak dengan menambah "s". Pakai dua kunci (`"Delete 1 item"` dan `"Delete {0} items"`).
- Jangan memanggil `tr` di properti statis, `const val`, atau konstruktor enum (nilainya beku pada bahasa saat load). Simpan kuncinya, terjemahkan lewat getter atau fungsi (contoh `Span.label`, `TaskKind.label`, `incomeTags()`).
- Kata yang tidak boleh diterjemahkan: nama merek, nama font, nilai teknis (path, perintah shell, kunci pref, MIME), label `Internal` dan `Root`.
- Semua tabel bahasa ada di `lang/`: `LangEn.kt` (`wordsEn`, daftar lengkap kunci, nilainya sama dengan kuncinya, jadi mudah dicari) dan `LangId.kt` (`wordsId`). Menambah bahasa: buat `LangXx.kt` berisi `val wordsXx: Map<String, String>` (salin `LangEn.kt` sebagai kerangka), lalu tambah satu baris `Language("xx", "Nama bahasa", wordsXx)` di `Lang.all`. Selesai; pilihan bahasa di Settings muncul otomatis. Kunci yang belum diterjemahkan jatuh ke Inggris.
- Setiap fitur baru: tambah kunci ke `LangEn.kt` dan semua `LangXx.kt` yang ada pada saat yang sama. Tidak boleh ada teks Indonesia (atau bahasa lain) tertulis langsung di kode; semuanya lewat `tr(...)`.
- Bahasa disimpan di `Cfg.language` ("system" mengikuti bahasa perangkat, bila tidak terdaftar jatuh ke Inggris). Format tanggal memakai `Lang.locale()`.

## 4. Sebelum menyerahkan hasil

1. Tidak ada komentar, tidak ada nama generik, tidak ada nesting sia-sia.
2. Pekerjaan berat sudah jadi Task, logika berat sudah di C++ dan lolos uji host.
3. Import, brace, dan signature diperiksa; `build.gradle.kts` dan `CMakeLists.txt` ikut diperbarui bila perlu.
4. Zip hasil memuat seluruh proyek, termasuk file ini.
5. Jawaban ke user ringkas: apa yang ditambah, apa yang belum diuji, apa yang perlu perhatian.

## 5. Catatan arsitektur

- Exclude list: nama atau pola `*` `?` pada semua kedalaman; dipakai Send to VPS dan Upload folder. Mode Move hanya menghapus file yang benar-benar terkirim.
- Emulator terminal sudah di C++ (`VtScreen`); `Term.kt` hanya pembungkus dengan API lama (cols, rows, cx, cy, history.size, lineAt, feed, resize).
- Perubahan: tombol Edit di penjelajah diganti Open (router) dan Read as text. `Nav.editing` dihapus, diganti `Nav.viewing`. Editor VPS sekarang lewat router yang sama.
- Save to phone (VPS) menyalin lewat `copyTracked` sebagai Task ke `Uplink/vps/{server}`.
- `FileSniff` hanya punya cadangan Kotlin minimal (cek byte nol); indeks baris tidak punya cadangan.
- Musik: `AudioPlayer` punya Resume/Pause, Repeat (Off, All, One), dan Shuffle; semuanya langsung ke ExoPlayer bersama sehingga ikut tampil di MediaSession.
- Browser: pembuatan WebView dibungkus try/catch, status awal dibaca di `WebHost.prime` (bukan saat komposisi), respons blokir iklan tanpa kode status, UA tanpa penanda WebView.
- Agent AI: tiap penyedia punya jenis API, base URL, API key, model, dan opsi tambahan opsional (system prompt, header tambahan satu per baris `Nama: nilai`, body JSON tambahan yang digabung ke permintaan). Permintaan jalan sebagai Task `TaskKind.Ask` (bisa dihentikan, memutus koneksi), balasan di-stream dan di-flush ke UI tiap 50 ms. API key disimpan di SharedPreferences, bukan di folder `Uplink`; riwayat obrolan di `Uplink/ai/chat.json` (maksimal 200 pesan). Menambah jenis API: tambah entri `AiApi`, lalu cabang di `AiClient` (`endpoint`, `applyAuth`, `buildBody`, `pieceOf`, `wholeOf`).
- Tasks pindah dari TOOLS ke NAVIGATION di drawer. Tampilan Tasks, `TaskStrip`, dan kartu task beranimasi (progres halus, ikon berdenyut saat jalan).
- `LangEn.kt` ditambah; `en` sekarang memakai `wordsEn`. Teks mentah tersisa (System, Buffers, Cached) sudah dibungkus `tr`.
- Kandidat berikutnya untuk C++: pencarian teks di editor, hashing/verifikasi hasil transfer, kompresi zip lokal.
- Agent AI: dialog penyedia hanya meminta nama (opsional), URL API, dan API key. `AiProbe` menormalkan URL (membuang `/chat/completions`, `/messages`, `/models`), mencoba `GET /models` dengan gaya OpenAI, Anthropic, lalu Gemini (urutan mengikuti host), memilih jenis API dari yang menjawab 2xx, dan memilih model otomatis (membuang embedding/audio/gambar/moderasi, menghindari snapshot bertanggal dan preview, mengambil `created` terbaru). Berjalan sebagai Task `TaskKind.Detect`. Model bisa dipaksa lewat Lanjutan; `AiProfile.pinned` menandainya. Gagal 401/403 dilaporkan sebagai API key ditolak.
- Fitur Metadata (stempel penulis) dihapus total: folder `stamp/`, mesin C++ `stamp.*`, harness `tools/stamp-test`, rute, menu file, tombol pilih, dan folder penyimpanan `metadata` tidak ada lagi. Jangan menambahkannya kembali kecuali diminta.
- Desain baru (permintaan user, menimpa batas animasi tak berujung di 2a2): semua layar punya gerak ambient. Komponen bersama di `Theme.kt`: `NxCard`, `nxGlass` (permukaan kaca dengan rim gradien), `NxSection` (label dengan garis). `NxGauge` dan `NxMeter` di `ui/NxGauge.kt`, `NxOrbit` (emblem orbit) di `ui/NxOrbit.kt`. Layar baru wajib memakai `NxCard`/`nxGlass`, `NxSection`, dan memberi gerak: `nxEnter` untuk blok statis, `nxRow` untuk baris Lazy, `nxFloat`/`nxNudge` untuk ikon. Semua gerak lewat `graphicsLayer` atau fase draw; jangan membaca state animasi di komposisi untuk ukuran atau padding.
- Performa animasi: gerak ambient harus berupa layer statis yang digeser lewat `graphicsLayer` (lihat `NxAmbient`), bukan digambar ulang tiap frame. `PathEffect` dibuat sekali lewat `remember`, bukan di dalam lambda draw. Animasi tak berujung di drawer hanya jalan saat drawer terlihat. Offset awal `StartOffset` selalu di-modulo durasinya.
- Tema global: `NxPalette` (Default, Obsidian, Galaxy) di `Theme.kt`, tiap palet punya `NxSkin` berisi seluruh token warna dan `glow` untuk latar `NxAmbient`. Setiap palet punya varian gelap dan terang (`NxPalette.skinFor(dark)`); sakelar Dark/Light (`NxMode.dark`) di Settings berlaku untuk palet mana pun. `NxMode.pick` menyimpan pilihan di pref `noxora_ui` (`palette`). Seluruh warna UI wajib lewat token `Nx*` (termasuk `NxGlow`); dilarang menulis `Color(0x...)` di layar baru. Pemilih tema ada di Settings > APPEARANCE (`PaletteCard`). Sakelar tema di bar VPS dihapus.
- Quick Actions di Home dihapus (permintaan user); semua pintasannya pindah ke drawer.
- Agen file (permintaan user): AI tidak pernah mengubah file sendiri. Model membalas satu objek JSON (`say`, `actions`, `inspect`). `inspect` (list, read) hanya baca dan jalan otomatis, maksimal 3 putaran. `actions` (create_file, mkdir, rename, copy, delete) hanya tampil sebagai rencana; user mencentang lalu menekan Terima atau Tolak, dan baru setelah Terima dijalankan sebagai Task. Penjaga di `FileAgent.guard`: Internal tidak boleh keluar dari folder penyimpanan, hapus atau pindah di `/`, root penyimpanan, dan folder tingkat atas Root/VPS diblokir, tujuan yang sudah ada diblokir, file yang sudah ada ditandai Timpa (merah). Memakai penyedia aktif di AI Agent.
- Model lokal GGUF untuk agen file belum ada: butuh llama.cpp di target `nxcore` dan jembatan JNI. Belum dikerjakan; `FileAgent` hanya bergantung pada `AiCall`, jadi penggantinya cukup menyediakan aliran teks yang sama.
- Deteksi AI: semua permintaan lewat `AiWire.connect` (User-Agent browser; bila 403 non-JSON dicoba ulang dengan UA curl), API key dibersihkan (spasi, tanda kutip, awalan Bearer), dan pesan error asli server ikut ditampilkan.
- Agen file, console (permintaan user, menimpa aturan `inspect`): model membalas `{say, console[], actions[]}`. `console` adalah daftar baris perintah yang dijalankan `ConsoleSession` (bukan shell asli, jalan di Internal, Root, dan VPS lewat `FsBackend`): baca langsung jalan (pwd, cd, ls, cat, head, tail, wc, stat, du, tree, find, grep), media langsung jalan (play, show), perubahan butuh persetujuan (mkdir, touch, cp, mv, rm, zip, unzip) dan tampil sebagai kartu rencana per langkah dengan baris `$ perintah`. `cd` tetap berlaku antar perintah dan antar putaran. Putaran baca maksimal 6, tiap putaran maksimal 30 perintah. Setiap perintah tampil di chat (`ConsoleLine`) dan keluaran penuh bisa dibuka (Show full); ke model hanya 4000 karakter per perintah.
- Console: `grep` dan `find` melewati `.git` dan `node_modules`; `grep` membaca maksimal 2 MB per file, melewati biner dan media, maksimal 4000 file dan 300 baris hasil. Pola tanpa karakter regex dicari lewat C++ (`TextGrep`, huruf besar kecil hanya ASCII), selain itu lewat Kotlin `Regex`. `cp`/`mv` ke folder yang sudah ada menaruh item di dalamnya. `rm` dan `cp` pada folder tanpa `-r` ditandai Blocked. `zip x` membuat `x.zip` di sebelahnya, `unzip` mengekstrak di sebelahnya. Penjaga `FileAgent.guard` berlaku sama untuk perintah console dan `actions`.
- Console media: `play` memutar lewat `Playback` (MediaSession) dan menampilkan kartu lagu dengan Play/Pause; `show` menampilkan foto/video (maksimal 12) sebagai thumbnail di chat, ketuk untuk membuka lewat `FileOpen`. File Root/VPS dipindah ke cache lewat `MediaStage` (Task) dan ditunggu sebelum ditampilkan. `decodeScaled` di `ImageViewer.kt` kini `internal` dengan parameter sisi.
- Fase agen di chat: Thinking, Designing structure, Writing code, Searching files (`AgentPhase`), dibaca dari aliran balasan model; ikon dan label berubah sesuai fase.
- Penjelajah Internal/Root: tombol Select masuk mode pilih (kotak centang di tiap baris), Select all, Deselect all, Done. Tekan lama tetap memilih.
- GitHub Integration (permintaan user): tombol GitHub di penjelajah membuka sheet penuh. Hanya GitHub API; semua hal tentang git CLI dihapus total (GitCli, pemasangan git, config global, jgit). Jangan menambahkannya kembali. Alur: isi username, email, token `ghp_` (diperiksa lewat `GET /user`), lalu hub: Upload, Browse, Actions, History/branch, pilih atau buat repo. Semua pekerjaan jaringan lama jalan lewat `TaskKind.Git`.
- Upload: lewat Git Data API (Internal, NoxoraStorage, Root; subfolder repo opsional, daftar skip dipakai, file identik dilewati dengan membandingkan SHA blob lokal C++ dengan pohon remote). Aditif atau dengan opsi hapus file yang sudah tidak ada. Blob lebih dari 95 MB dilewati.
- Browse: daftar isi repo per branch, edit teks sampai 1 MB, buat file, buat folder (lewat `.gitkeep`), hapus file atau folder (satu commit lewat tree dengan sha null), unduh file, folder, atau seluruh branch ke folder aktif. Actions: daftar run (filter branch, polling 15 detik selama ada run berjalan), artifact per run atau seluruh repo, unduh ke folder mana pun (path bisa diganti, otomatis subfolder bernama artifact) dengan opsi ekstrak, Re-run dan Cancel.

- Jalur isi `nx write`: satu jalur, argumen. `nx write <path> '<teks>'` (teks maksimal 20.000 karakter, `\n`, `\t`, `\\` diterjemahkan). File panjang tetap lewat daftar `files` milik agen (`AgentTarget.write`), mekanisme lama yang tidak diubah selain konfirmasinya kini lewat `AgentConfirm`. `nx help` menyebut keduanya.
- `nx edit <path> <lama> <baru>`: teks lama harus tepat satu kali (kemunculan tumpang tindih dihitung). Nol atau lebih dari satu ditolak dengan jumlahnya, dan petunjuk CRLF bila baris baru tidak cocok. File di atas 1 MB, biner, atau bukan UTF-8 valid ditolak supaya tidak rusak. Tidak ada konfirmasi (file tidak hilang), hanya penjaga path.
- `agentGuard` punya parameter `replace` (default false). Hanya `nx cp`, `nx mv`, `nx zip`, `nx unzip` yang memberi true, jadi jalur lain (shell biasa, kartu agen file, `actions`) tetap menolak "target already exists". Hasil kedua `agentGuard` untuk Copy/Rename kini true bila target file akan ditimpa.
- `NxTransfer.resolve`: tujuan folder yang ada berarti taruh di dalamnya dengan nama sumber. Menimpa file memerlukan konfirmasi. Menimpa folder, folder menimpa file, folder ke dalam dirinya sendiri, dan sumber sama dengan tujuan ditolak. Alias storage (`/sdcard`, dst.) dikanonkan lewat `DeletePolicy.canonical`.
- Satu jalur konfirmasi: `AgentConfirm.ask` memakai `NxConfirm` (kepala "Delete N items" atau "Replace N items", satu baris per nama kanonik, folder diberi akhiran `/`) dan `ApprovalBoard`. Dipakai oleh `PhoneAgentTarget.run` (rm, rmdir, mv), `PhoneAgentTarget.write`, dan semua perintah nx. `DeletePolicy.needsConfirm` kini memuat `cp`, `write`, `zip`, `unzip` selain `rm`, `rmdir`, `mv`.
- `nx rm [-r] <path>...`: maksimal 50 nama, tanpa wildcard, folder wajib `-r`. Semua target diperiksa dulu (`DeletePolicy.refusal` lalu `agentGuard`); satu target terlarang membatalkan seluruh panggilan sebelum bertanya. Penghapusan yang menyertakan folder berjalan sebagai Task `TaskKind.Delete`.
- `nx cp`: selalu Task `TaskKind.Copy` (`copyTracked`, bisa dihentikan, progres file dan byte). Menimpa file: salin ke `<tujuan>.nxnew` lalu `replaceFile`. `nx mv`: `FsBackend.rename` langsung (cepat pada perangkat yang sama), menimpa lewat `replaceFile`. Catatan: `InternalFs.rename` jatuh ke salin lalu hapus bila lintas volume, dan itu tidak dilacak sebagai Task.
- `replaceFile` (di `NxChangeTools`): tujuan lama dipindah ke `<tujuan>.nxold`, sumber dipindah ke tujuan, cadangan dihapus; bila langkah kedua gagal cadangan dikembalikan. Dipakai cp, mv, dan zip agar kegagalan di tengah tidak menghilangkan file lama.
- `nx zip <sumber> <tujuan.zip>`: HP memakai `ZipFs` (zip4j) lewat Task `TaskKind.Zip`, dibangun ke `<tujuan>.nxnew` lalu dipindah. VPS memakai `zip -rq` di server lewat `Vps.stream` bila probe `nx env` menunjukkan `zip` ada; bila tidak ada, pesan "tidak tersedia". Zip tidak boleh dibuat di dalam folder yang dikemasnya. Menimpa zip yang ada butuh konfirmasi. Penyimpanan Root tidak didukung.
- `nx unzip <zip> [folder]` (default: folder bernama sama di sebelah zip): HP membaca daftar entri dari `java.util.zip.ZipFile` lebih dulu, `NxUnzip.plan` menolak seluruh arsip bila ada entri yang keluar dari folder tujuan (`..`, path absolut, huruf drive, backslash, NUL), jumlah entri di atas 50.000, atau total ukuran terdeklarasi di atas 2 GB. Saat ekstrak, `NxUnzipMeter` menghitung byte yang benar-benar ditulis sehingga header palsu tetap kena batas. Entri yang akan menimpa file butuh konfirmasi yang menyebut tiap nama; lebih dari 30 file tertimpa ditolak (saran: ekstrak ke folder kosong) supaya tiap nama tetap bisa disebut. File di atas folder atau sebaliknya ditolak. Zip berpassword belum didukung oleh `nx unzip` (ZipFile JDK). Symlink tidak dibuat. VPS: daftar nama (`unzip -Z -1`) dan total (`unzip -Z -t`) diperiksa dengan logika yang sama lalu `unzip -n` (file yang ada dipertahankan, tidak ditimpa; ini beda dari HP).
- `VpsProbe` ditambah `unzip` (`TOOLS` dan skrip). `NxEnvReport.vpsTools` mengembalikan hasil probe ter-cache untuk dipakai perintah arsip.
- Penyimpangan sadar dari aturan C++: kompresi dan ekstrak memakai zip4j dan `java.util.zip` yang sudah native/matang dan sudah dipakai `ZipFs`, tidak ada kode CPU-bound milik app yang baru. Pemindaian ukuran untuk progres zip tetap lewat `TreeScan` (C++).
- Belum dikompilasi, `NxStageFourTests` belum dijalankan (tidak ada kotlinc, Gradle, Android SDK di lingkungan pembuat). Belum dicoba di HP dan VPS nyata: konfirmasi di UI, `zip`/`unzip` server, `mv` lintas volume.

## Tahap 5 prompt nx lengkap: jaringan (`nx fetch`)

- `nx fetch <url> [offset]`, butuh internet (`NxNeed.Internet`, ditolak `NxPick` saat offline). Logika murni di `onetool/NxFetch.kt` (`NxFetchUrl`, `NxFetchAddress`, `NxFetchRedirect`, `NxFetchDomains`, `NxFetchBody`, `NxHtmlText`, `NxFetchPage`), diuji di `NxStageFiveTests`. Lapisan Android `onetool/NxFetchTools.kt`. Berjalan sebagai Task `TaskKind.Fetch` lewat `NxTask.await`; penolakan alamat tidak menjadikan Task gagal, jadi tidak masuk Task Error.
- Penjaga alamat (`NxFetchUrl.check`, jalan sebelum koneksi apa pun): hanya http dan https, tanpa user:password, tanpa backslash atau karakter kontrol, wajib diawali `http://` atau `https://`. Host diambil sebelum `/`, `?`, `#`. URL yang dipakai untuk koneksi dirakit ulang dari host yang sudah divalidasi, bukan string asli. Ejaan IPv4 alternatif (desimal, hex, oktal, `127.1`) diurai seperti `inet_aton` lalu ditulis ulang bentuk bertitik. IPv6 diurai sendiri, termasuk bentuk mapped, NAT64, 6to4, Teredo.
- Ditolak: 0.0.0.0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.168/16, 192.0.0/24, 198.18/15, 224.0.0.0 ke atas; IPv6 `::`, `::1`, fc00::/7, fe80::/10, fec0::/10, ff00::/8, dan alamat IPv4 yang disisipkan di bentuk mapped/NAT64/6to4. Nama `localhost`, `*.localhost`, `*.local`, `*.internal`, `*.lan`, `*.home.arpa`, `*.localdomain`, `*.intranet`, `*.corp`, dan nama tanpa titik. Daftar ini lebih luas dari prompt (CGNAT, multicast, reserved, ULA, nama lokal) dengan sengaja.
- Nama host di-resolve di dalam Task (`InetAddress.getAllByName`); bila SATU saja hasilnya masuk rentang di atas, seluruh permintaan ditolak (menutup `127.0.0.1.nip.io` dan sejenisnya). Batas yang diketahui: koneksi dibuka dengan nama host, bukan IP hasil resolve, jadi jendela DNS rebinding antara cek dan koneksi belum tertutup (`HttpURLConnection` tidak bisa dipasangi resolver sendiri; menutupnya butuh OkHttp dengan `Dns` khusus atau soket manual).
- Pengalihan diikuti manual (maksimal 5): tiap lompatan melewati penjaga alamat, cek DNS, dan persetujuan domain lagi. https ke http ditolak. Tidak ada cookie atau header otorisasi yang dikirim.
- Batas: connect 10 detik, baca 15 detik, 30 detik per lompatan, badan 2.000.000 byte (dihitung setelah dekompresi, berhenti membaca di batas), keluaran ke model 4000 karakter. Tipe biner (gambar, pdf, zip, dst.) ditolak dari header tanpa mengunduh; tipe kosong atau octet-stream diendus dari byte awal (byte nol = biner). Karakter set: header, BOM, lalu `<meta charset>`, bawaan UTF-8.
- Keluaran: baris `Fetched <url> (<tipe>, <ukuran>)`, `Title:` bila ada, lalu teks. HTML diubah jadi teks (`NxHtmlText`): script, style, noscript, template, svg, iframe, object, canvas dibuang; tag blok jadi baris baru; `li` jadi `- `; h1 sampai h6 jadi `#`; tabel tanpa pipa; `pre` menjaga spasi; entitas umum dan numerik didekode. Teks panjang dipotong di batas baris dan pesannya menyebut `nx fetch '<url>' <offset>`; halaman terakhir diambil dipegang 5 menit di memori supaya lanjutan tidak mengunduh ulang dan tidak berubah di tengah jalan.
- Persetujuan domain: host baru meminta izin lewat `ApprovalBoard` (kartu Izinkan/Tolak, notifikasi bila app tidak terlihat, maksimal 10 menit). Izin berlaku per host persis (`www.example.com` dan `example.com` dihitung berbeda) sampai app ditutup, hanya di memori (`NxFetchDomains`). Penolakan tidak diingat.
- PERTANYAAN TERBUKA untuk pemilik: apakah izin domain berlaku untuk semua domain, per domain, atau per domain yang bertahan setelah app ditutup. Prompt menyatakan keputusan ini belum ada, jadi yang dipasang hanya perilaku paling sempit yang masih bisa dipakai (per host persis, per sesi). Mengubahnya cukup di `NxFetchDomains` dan `NxFetchTools.askDomain`.
- Penyimpangan sadar dari aturan C++ (seperti `nx hash` dan `nx zip`): HTML ke teks berjalan di Kotlin karena masukan dibatasi 2 MB, satu kali lintas linear, dan tes `largeInputIsLinear` memeriksa waktunya. Kalau nanti perlu halaman lebih besar, pindahkan `NxHtmlText` ke C++ dengan cadangan Kotlin yang setara.
- `nx fetch` bukan browser: tidak menjalankan JavaScript, jadi halaman yang isinya dibuat oleh JS kembali hampir kosong. Untuk itu tetap `nx web` lalu `nx text`.
- Belum dikompilasi dan belum diuji (tanpa kotlinc, Gradle, Android SDK). Belum dicoba di HP: URL publik, kartu persetujuan, pengalihan, Cleartext http (manifest sudah `usesCleartextTraffic=true`).

## Tahap 6 prompt nx lengkap: skrip, paket, dan penghapusan di VPS

- Perintah baru, hanya di VPS (`NxNeed.Vps`, ditolak `NxPick` bila VPS tidak tersambung, dan ditolak `NxRunTools` bila target aktif adalah HP): `nx node <file> [args]`, `nx py <file> [args]`, `nx install [apt|npm|pip] <paket>...`. Logika murni di `onetool/NxRun.kt` (`NxRun`, `NxInstall`, `NxShellRmParse`, `nxQuote`), diuji di `NxStageSixTests`. Lapisan Android `onetool/NxRunTools.kt`. Jalan sebagai Task `TaskKind.Run` dan `TaskKind.Package` lewat `NxTask.await`; skrip yang keluar dengan kode bukan nol tidak menjadikan Task gagal, jadi tidak masuk Task Error.
- `nx node` dan `nx py`: file wajib berekstensi `.js .mjs .cjs` atau `.py`, nama file tidak boleh diawali `-` (tidak ada `-e` atau `-c`, jadi tidak ada kode inline). Maksimal 20 argumen, tiap argumen 500 karakter, tanpa baris baru atau NUL; semuanya dikutip dengan `nxQuote`. Berjalan di folder kerja target dengan `</dev/null` (tidak ada input) dan `timeout 600` bila `timeout` ada di server. Keluaran ke model: 4000 karakter TERAKHIR (galat ada di ujung), awalnya diberi catatan jumlah karakter yang dipotong. Kode keluar bukan nol ditulis di baris akhir, kode 124 menjadi "Stopped after 10 minutes". File di atas 256 KB ditolak. Probe `nx env` (`node`, `python3`) dipakai untuk menolak lebih awal.
- Penjagaan isi skrip: 256 KB awal file dipindai dengan `shieldReason` (diblokir) dan `approvalReason` (kartu persetujuan ApprovalBoard) yang sama dengan baris shell VPS. Pemindaian hanya melihat file yang dijalankan, bukan modul yang diimpornya, dan berbasis pola (bisa salah positif seperti `fs.rm`).
- `nx install`: SELALU meminta persetujuan (kartu menyebut perintah persisnya), tidak ada jalur tanpa konfirmasi. Manajer: `apt` (bawaan bila kata pertama bukan nama manajer), `npm`, `pip`. Maksimal 10 paket, nama divalidasi per manajer (`NxInstall.allowed`): tidak boleh diawali `-`, tidak boleh URL, path, `git+`, rentang versi, atau karakter shell; versi hanya bentuk `apt pkg=versi`, `npm pkg@versi`, `pip pkg==versi`. apt: `apt-get update -qq` lalu `apt-get install -y` dengan `DEBIAN_FRONTEND=noninteractive`; bukan root diganti `sudo -n` dan bila sudo butuh password dilaporkan, tidak pernah menanyakan password. npm: `npm install --no-fund --no-audit` di folder kerja (tanpa `-g`). pip: `python3 -m pip install --no-input` (tanpa `--user`); server yang menolak (externally-managed-environment) mendapat petunjuk memakai venv. Manajer yang tidak ada di server dilaporkan tanpa menjalankan apa pun.
- Penghapusan di SSH: baris shell VPS berbentuk `rm [-rRfvdI | --recursive --force --verbose --dir] [--] path...` yang polos (tanpa kutip, glob, `$`, `~`, rantai, pipa, kurung) kini memakai jalur yang sama dengan HP: `agentGuard` (akar dan folder tingkat atas ditolak), lalu `AgentConfirm.ask` yang menyebut tiap nama kanonik (folder berakhiran `/`). Path yang tidak ada tidak dicantumkan. Baris `rm` yang tidak polos tetap memakai persetujuan per baris perintah lama (`approvalReason`), karena nama target tidak bisa dipastikan sebelum shell memprosesnya.
- `nx env`: baris "Phone nx commands" kini tidak lagi memuat perintah khusus VPS, ada baris "VPS only nx commands" saat VPS tersambung. Semua entri `NxCatalog` kini `ready`, bagian "planned" di `nx help` dihilangkan saat kosong.
- PERTANYAAN TERBUKA untuk pemilik: (1) apakah `nx install` tanpa nama manajer sebaiknya selalu apt (sekarang begitu) atau wajib menyebut manajer; (2) apakah `nx node` dan `nx py` perlu persetujuan setiap kali (sekarang hanya bila isi file cocok pola berbahaya); (3) apakah `npm install -g` dan `pip --user` perlu didukung. Yang dipasang adalah perilaku paling sempit; mengubahnya cukup di `NxInstall.command` dan `NxRunTools.execute`.
- Batas yang diketahui: saat Task dihentikan, koneksi SSH diputus tetapi proses di server baru berhenti oleh `timeout` (10 menit) atau saat kanalnya ditutup server; bila `timeout` tidak ada di server, batasnya hanya 15 menit milik `Vps.stream`. Skrip yang menunggu input akan mendapat EOF, bukan menggantung.
- Belum dikompilasi dan belum diuji (tanpa kotlinc, Gradle, Android SDK). `NxStageSixTests` belum dijalankan. Belum dicoba di VPS nyata: `nx node`/`nx py`, `apt-get` dengan dan tanpa root, `sudo -n`, `npm install`, `pip` di Debian/Ubuntu baru, kartu persetujuan, dan konfirmasi `rm` lewat SSH.

## Tahap 7 prompt nx lengkap: format hasil dan retry

- Format: tidak ada tabel dengan pipa di chat. Keluaran `nx ls` dan `nx du` satu bentuk: total di baris pertama, lalu satu baris per item `ukuran  nama  keterangan`, terbesar dulu, ukuran dalam B/KB/MB/GB. Folder yang belum diukur ditulis `not counted yet` (belum dihitung), bukan `-` atau tebakan; `nx ls` tidak mengukur folder, untuk itu `nx du`. `nx ls` kini urut ukuran bawaan, `-n` urut nama (flag `-S` lama tidak dipakai lagi).
- Balasan model (`say`) dibersihkan dari tabel pipa lewat `NxNoPipes.clean` (baris `| a | b |` jadi `a  b`, baris pemisah dibuang). Keluaran perintah TIDAK disentuh (isi file yang dibaca harus tetap persis). Prompt agen (`TermAgent.rules`) memuat aturan formatnya.
- Pemadatan ke model: `OneTool.forModel` (`NxCondense.forModel`, batas 4000 karakter). Teks yang muat dibiarkan. Yang lebih panjang dirapatkan dulu (spasi akhir, baris kosong beruntun, baris kembar jadi `(xN)`), bila masih panjang diambil awal 55% dan akhir 45% dengan satu baris penanda jumlah karakter yang dibuang. Tampilan di UI tetap penuh.
- Retry: `NxRetry` (satu ledger per tahap agen di `TermAgent.stage`, dipakai lewat parameter `retry` di `OneTool.run`). Di HP, nama di luar shell bawaan dan bentuk berbungkus (`toybox`, `busybox`, `env`, `sudo`, `command`, `exec`, `nohup`, `time`, atau path mutlak) ditolak SEKALI dengan saran padanan nx (`du` ke `nx du`, `cat` ke `nx read`, `sha256sum` ke `nx hash`, `curl` ke `nx fetch`, dst.; tabel `NxRetry.twins`, tes memastikan semuanya ready di katalog). Ejaan lain dari perintah yang sama dijawab `Already refused` tanpa dijalankan. Bentuk polos yang memang ada di shell HP (`du`) tetap jalan. Di VPS bungkus jalan seperti biasa, tetapi "command not found" atau aksi nx yang ditolak (`needs a connected VPS`) dicatat sebagai ditolak dan tidak dicoba ulang dengan variasi nama. Maksimal dua percobaan gagal per tujuan (nama perintah + argumen non-flag pertama); percobaan ketiga ditolak dengan daftar apa yang sudah dicoba supaya agen melapor ke user. Keberhasilan menghapus hitungan tujuan itu.
- Batas yang diketahui: "tujuan" didekati lewat kunci nama + argumen pertama, jadi dua pendekatan berbeda ke file yang sama (misalnya `nx edit` dengan teks lama berbeda) tetap dihitung satu tujuan, sesuai aturan dua percobaan. Pengenalan "perintah tidak ada" lewat pola teks (Inggris dan Indonesia); keluaran shell berbahasa lain tidak dikenali. Ledger hidup per tahap agen, tidak lintas sesi.
- Belum dikompilasi dan belum diuji (tanpa kotlinc, Gradle, Android SDK). `NxStageSevenTests` belum dijalankan. Perlu dicek di HP: `nx sh 'toybox du'` menghasilkan satu penolakan dan saran `nx du`, lalu `busybox du`, `/system/bin/du`, `env du` menghasilkan `Already refused`.
